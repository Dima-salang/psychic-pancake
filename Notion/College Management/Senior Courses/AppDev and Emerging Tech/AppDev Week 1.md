## 👨‍🏫 Lecture 1: Application Development and Methodologies


### 1. Defining Application Development

At its heart, **application development is the process of creating a computer program or a set of programs to perform the different tasks required by business.** This is the fundamental goal of our profession—to translate human needs into automated, digital solutions.

The scope of this work is vast. The lecture content notes that **application development can be done by a single freelance developer or massive organization.** This means the same underlying principles apply whether you are building a simple utility script for a small business or working on a colossal, globally-distributed system like an online banking platform.

Crucially, AppDev is not random coding; **it defines the process of how the application is made and generally follows a standard methodology.** The methodology provides the structure needed for coordination, quality control, and predictable delivery, which are essential for professional engineering.

### 2. Factors to Consider in Application Development

Before any development begins, a project manager or architect must evaluate several critical factors, as these will heavily influence the choice of methodology and team structure:

* **Project Size and Scope:** **The size of the project is a factor that you need to consider.** Large projects inherently carry greater complexity and risk, requiring more rigorous planning and architecture. This ties into **other project requirements like how specific or the details the scope of the project**. High detail suggests a lower chance of change, while vague scope suggests high volatility.
* **Customer Involvement and Change:** We must assess **how much the customer will want to change things.** This is the primary indicator for selecting an adaptive methodology like Agile over a predictive one like Waterfall.
* **Team Resources:** **The development team should also be identified onto how large or how experienced you need when it comes to the project to commit with the deadlines specified on the contract.** Having an experienced team allows for greater speed and autonomy, while less experienced teams require more detailed oversight and process definition.

### 3. The Software Development Life Cycle (SDLC)

Regardless of the methodology chosen, every application goes through the essential phases of the **Software Development Life Cycle (SDLC)**. The lecture identified the key stages: **planning, analysis, design, construction, testing, implementation, and support.**



This cycle provides the roadmap. Methodologies simply define *how* we move through these stages and *how frequently* we loop back.

### 4. Application Development Methodologies

Most approaches in our industry are grouped into three key categories: **waterfall**, **rapid application development (RAD)**, and **agile**.

#### A. Waterfall Development

Waterfall is the oldest, most traditional methodology.

* **Core Principle:** It is a linear, sequential model that assumes stability. **The waterfall method assumes that the project requirements are clear and the customer and project manager have a unified and Clear Vision about the end result.**
* **Sequential Flow:** The process is strictly ordered: **requirement, design, implementation, verification, and maintenance.**
* **The Constraint:** **It is called waterfall because once you go down you can go back up everything flows downward.** This means changes discovered late in the cycle are extremely costly, as they necessitate revisiting and re-approving previous phases.
* **Best Use Cases:** Waterfall **works best as an application development method when:**
    * **you don't anticipate changes.**
    * **the budgets are fixed for the project.**
    * **you've done a similar project before** (low technical risk).
    * **the customer is very clear and doesn't plan to be involved much until the end of the project.**

#### B. Rapid Application Development (RAD)

RAD, in many ways, is **the opposite of the waterfall method.** It prioritizes speed and user involvement.

* **Core Principle:** **Based mostly on prototypes and the goal is to produce a working version of the application as quickly as possible and then to continuously iterate afterwards.**
* **Prototype Focus:** The core idea is that **rad is never too attached to a prototype and is always willing to change it to suit the needs of the customer.** Prototypes are used as communication tools, designed for quick feedback rather than production quality.
* **Scope Constraint:** RAD is typically recommended **for projects within six months period** due to its intense focus and scope-creep risk.
* **Best Use Cases:** RAD is ideal when you have:
    * **an experienced team of developers.**
    * **a highly engaged customer.**
    * **a flexible delivery date and pressing business** need.

#### C. Agile Development

Agile represents the industry standard for complexity and change management.

* **Core Principle:** **Agile is iterative like Rad but focuses on building features one at a time.** It follows the **Agile Manifesto**, valuing working software over documentation and responding to change over following a plan.
* **Mechanism (Sprints):** **It uses sprints or set of time when a certain feature should be built tested and presented.** A Sprint is a fixed-length iteration (typically 2-4 weeks) during which a cross-functional team completes a small, functional increment of the product.
* **SDLC Integration:** **It tries to incorporate the entire stlc for a feature into each Sprint.** This means planning, coding, and testing for that feature are all completed within the Sprint timebox.
* **Output Focus:** **Agile doesn't focus on prototypes but only presents completed work after the Sprint is over.** The output is a "potentially shippable increment" of production-quality code.
* **Best Use Cases:** Agile is a great application development methodology when:
    * **the project is large enough to break down into several sprints.**
    * **you have lots of Specialists who can work on a team together.**
    * **the bulk of the project is known ahead of time and can be planned out** (the long-term roadmap is clear).
    * **you have good project leaders in place** (e.g., Product Owner and Scrum Master).

## 📚 Lecture 3: Types of Application Development and Frameworks

Welcome back, class. Today, we shift our focus from the *process* of application development to its various *categories* and the powerful tools we use to build them efficiently. Understanding these different types is crucial for career specialization and for defining project scope.

### 1. Categorization of Application Development

Application development is a broad field, but it can be broken down into six major categories based on the product's function, scale, and environment.

The main **types of application development can be categorized as custom application development, low code, mobile application development, database application development, Enterprise application development, and web application development.**

---

### 2. Custom Application Development

This category addresses unique, bespoke needs that commercial off-the-shelf (COTS) software cannot satisfy.

* **Definition:** **Custom application development is designing of software applications for a specific user or group of users within an organization.** This **custom software is designed to address specific needs within an organization as opposed to more traditional standard software used by the masses.**
* **Theoretical Advantage (Perfect Fit):** Custom software is **tailor made for the business and eliminates the need to change the business procedures to fit a pre-developed software product.** This is a significant competitive advantage, as it preserves unique business processes.
* **Practical Benefits:**
    * **Cost Efficiency:** It can generally **save on Hardware acquisition costs as the solution is designed with the existing infrastructure and does not carry unused features that increase Hardware requirements.**
    * **Direct Support:** **The company has full access to the original development team so any issues that arise can be resolved quickly and efficiently.** This is a significant benefit over waiting for a mass-market software vendor's patch.
    * **Ownership:** **The intellectual property rights of the software is still owned by the company** which provides long-term control and strategic flexibility.

---

### 3. Low-Code Application Development (LCAD)

Low-Code is a revolutionary trend democratizing application creation.

* **Definition:** **Low code is a way to design and develop applications with little or no coding.** **Local platforms offer intuitive visual Builders, ready to use code Snippets, form and Report templates, and built-in connectors that speed development and extend the ability to innovate to a broader set of people.**
* **Practical Workflow:** **Users can jump right in to building the application as this platforms eliminate typical processes like creating Frameworks, modeling data, and developing user interfaces.** The drag-and-drop interface dramatically reduces the barrier to entry.
* **Advantages:**
    * **Ease of Use:** An **intuitive drag and drop interface makes it easy for both users and developers to create applications.**
    * **Speed:** **Ready to use code Snippets and templates allow you to accelerate application development.** This aligns perfectly with the goals of Rapid Application Development (RAD) and Agile.
    * **Maintenance:** **Whenever an update is available all the applications running on the platform are automatically updated, ensuring complete safety of your data.**

---

### 4. Specialized Development Types

The remaining categories are defined primarily by the environment or function of the application:

#### A. Mobile Application Development
* **Focus:** **Mobile application development is the process of creating apps that run on any mobile platform regardless it is Android and iOS.**
* **Industry Trends:** Conventionally, this was a **rigorous and effort intensive process** (requiring native code like Swift/Kotlin). However, the lecture notes that **low code mobile app development platforms are now available to simplify the process**, allowing developers to build cross-platform apps faster (e.g., using frameworks like React Native or Flutter, or specialized LCAD platforms).

#### B. Database Application Development
* **Focus:** **Database applications are designed to collect organize and manage information efficiently.**
* **Functionality:** **They're used to sort data by criteria, perform calculations, create reports and share information with team members.** These are the backend systems fundamental to nearly all modern business operations, from tracking inventory to managing customer relationships.

#### C. Enterprise Application Development (EAD)
* **Definition:** **Enterprise applications are on premises software or cloud-based apps that serve the needs of large often global organizations such as corporations, Banks, and government agencies.** Examples include ERP (Enterprise Resource Planning), CRM (Customer Relationship Management), and SCM (Supply Chain Management) systems.
* **Challenges and Low-Code Solution:** Traditional EAD is **time consuming, cost intensive and requires a sizeable Workforce of Developers**. The lecture points out that **these challenges can be overcome with the low code approach to Enterprise app development**.
* **Enterprise Benchmarks (Theoretical Requirements):** EAD requires meeting strict criteria:
    * **Scalability:** **It must work across multiple devices, networks and teams distributed over continents and time zones.**
    * **Security:** **This is a must and should allow users with varying levels of permissions to access information they need while securing confidential data.** This involves roles, permissions, and robust encryption.
    * **Efficiency:** The software **must be easy to build an update when it comes to the software and it should reliably handle large amounts of data and many concurrent users.**

#### D. Web Application Development
* **Definition:** **A web application is interactive software built to solve a specific need.** **It has a user-friendly interface backed by a database that allows users to easily access the data from any internet connected computer.**
* **Examples:** **The most common examples of web applications are online banking, ticket booking websites, e-services or email Services, e-commerce applications and more.** This is perhaps the most ubiquitous type of application today.

---

### 5. Application Frameworks

Regardless of the application type, developers rarely start from scratch. They rely on **Application Frameworks**.

* **Definition:** **It is a software library that provides a fundamental structure to support the development of applications for a specific environment.** **It is a body of pre-written code acting as a template or skeleton which a developer can then use and reuse to create an application by filling in their code as needed to get the app to work as they intend.**
* **Practical Goal:** **Reuse the Frameworks enables developers to program their application without the manual overhead of creating every line of code from scratch.** This allows the developer to **concentrate more on business logic rather than worrying about common pieces of code used to cross a domain or application.**
* **Theoretical Foundation (Inversion of Control):** The key concept here is **Inversion of Control (IoC)**, where the framework calls the developer's specific code, rather than the developer's code calling the framework. 
* **Advantages of Frameworks:**
    * **Componentization:** This **allows developers to use it in a piece by piece fashion** leading to better allocation of resources and **a lower cost of development.**
    * **Quality & Extensibility:** **Code and design reusability helps in the usage of tested components which increases the quality and extensibility for customizing the framework to implement business requirements.**
    * **Simplicity & Security:** **Simplicity is achieved by the encapsulation feature which helps control components access and provide data security.**
    * **Maintenance:** **Better code maintenance because all the base code is centralized in a single location.**

The use of frameworks provides **a better beginning for software development and aids in Rapid application development** by handling the foundational infrastructure.
